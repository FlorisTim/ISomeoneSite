["title"]Animation DSL[/] ["post spckbd"] ["title"]2026 June[/] The animation DSL uses string replacement to make typing them out faster, it first parses all "references", for example
<item>\[ **MOVE **%010 10; \] <item>\[**neg\] <item>\[**blank\] this turns into:
**MOVE -10 10; **MOVE 10 10; it has about 20 instructions, the movement and rotational instructions can have a timer extension
**MOVE_X**-t1 15 10 this expects a magnitude and speed, magnitude means how far it will move or how much it will rotate, and the speed decides how fast the motion is, t1 is a sine wave, t2 is a cosine wave, there are also enums and variables, these are compile-time only **var big 25; **enum torso upperarm lowerarm upperleg lowerleg; after something like this is typed anytime a token is "big" or "-big" it will get replaced with the byte that defined it, or in case of the enum the index in the arguments, this makes code more readable and usefull, but as i said this is all compile time so the generated bytecode does not save any of it.
there is one last command worth noting, and thats the "do" command, this injects the contents of a file before compiling it
**do \[Assets/Animations/AnimLib.anim\]; will turn into **enum timer; **enum walkTimer attackTimer; if that is the contents of the file at Assets/Animations/AnimLib.anim
