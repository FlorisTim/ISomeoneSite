["title"]AI DSL[/] ["post spckbd"] ["title"]Added in 2026 July[/] This is a DSL i specifically made for the entities in dunge, the idea was to have code that is easy to mutate at runtime for varying behaviour.

The language itself is based on the animation dsl, but this languages features more comprehensible syntax, like inline functions (addition as +, subtraction as -, etc..).
and comparisons too.

however, the parser that turns all that text into bytecode still expects only simple functions, so what it does is it turns: IF a + b == c ( ... )
into SWITCH_SLOT 0; ADD a b; IFEQ result0 c ( ) making it into a list of functions easier to parse than the previous text.
there are also act functions, and query functions **autovar Target; **autovar XDistance; SET_VAR Target : nearest ˜? player; SET_VAR XDistance : getX ˜! myself; SET_VAR XDistance : XDistance - getX ˜! Target; but i also allowed for the syntax to be a bit more readable in the following example SET_VAR Target : nearest?{player}; SET_VAR XDistance : getX{myself}; SET_VAR XDistance : getX{#Target} - -#XDistance;
this is a simple change but makes it so much more readable.
you may have noticed that the way i typed out the last bits of code might seem weird, but it's for a very specific reason, the order of operations is from left to right, so something like SET_VAR XDistance : getX{myself} - getX{#Target}; would become SET_VAR XDistance : getX ˜! myself - getX ˜! #Target; and in code, "getX" is the third operation, making the eventual output be SET_VAR XDistance : 3 ˜! myself - 3 ˜! #Target; and going from left to right would totally ruin the functionality of this, however this is not a big deal as most of the ai code is going to be templates, where more complex behaviour is generated on top, for example a zombie's normal ai would be move towards player, attack, move back, repeat, but a zombie with one leg might walk shaky, or a delusional zombie might look for the nearest player, only for it to return the nearest zombie, this way gameplay is still fun.
